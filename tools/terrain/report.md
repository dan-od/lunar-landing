# Terrain horizon preparation — report

Scope: `tools/terrain/`. Reads the south-pole elevation map and turns a lunar
point into a horizon profile (360 directions, degrees clockwise from north).
Covers PRD "How terrain is prepared", requirement **4-1** (grid of profiles
around the demo site) and requirement **F-6** (direction convention verified).

Model: **terrain** (LDEM_80S_80MPP, bilinear-sampled). Every number below is
read from the GeoTIFF or from a coordinate transform defined by the file's own
CRS; nothing is invented. Generated data (profiles, plot) and the virtual
environment are not committed — regenerate with the commands at the end.

## The elevation map, as the file reports it

| Property | Value (read from the file) |
| --- | --- |
| Size | 7600 × 7600 pixels, 1 band, float32, nodata = NaN |
| Pixel size | 80 m × 80 m |
| Extent | ±304 000 m east and north (608 km square) |
| Projection | Polar Stereographic, latitude of origin −90°, central meridian 0° |
| Body | IAU "Moon (2015) - Sphere", ocentric, radius **1 737 400 m** |
| Axis note | CRS lists **both** axes as `NORTH` — grid "up" is not true north except on the 0° meridian (the convention risk F-6 exists to catch) |

Elevation at the IM-2 target (84.78 S, 29.13 E): **5312.7 m** above the
reference sphere, by bilinear interpolation. This is in range for the Mons
Mouton massif, so it reads as plausible rather than wrong.

## Conventions (how the model works)

- **Observer:** 2 m above the surface (bilinear elevation + 2 m).
- **Range:** rays walk out to **150 km** where the map allows; the distance at
  which a ray leaves the map is recorded per direction. Step starts at 40 m and
  grows to 3 % of distance, so the near field is fine and the far field is cheap.
- **Curvature:** each sample's angle is `atan2(Δh − d²/2R, d)` with
  R = 1 737 400 m. Check: a 6 km massif 100 km away gives
  `atan((6000 − 2878)/100000) = 1.79°`, matching the briefed ~1.8°.
- **Sampling:** bilinear, because the 40 m grid is finer than the 80 m pixels.
- **Direction:** azimuth is degrees **clockwise from north toward east**; the
  map step direction for azimuth A at longitude L is `(sin(L+A), cos(L+A))`.

## Direction convention check (F-6)

Verified from the projection and independent geodesy, **not** from any stated
formula:

- **North/East vectors.** Stepping 1 km along `(sin L, cos L)` raises latitude
  with longitude unchanged; stepping along `(cos L, −sin L)` raises longitude
  with latitude unchanged. So local north = `(sin L, cos L)`, local east =
  `(cos L, −sin L)` — confirmed, not assumed.
- **Azimuth = true bearing.** For azimuths around the whole circle, a map step
  along `(sin(L+A), cos(L+A))` has a true geodesic bearing (pyproj `Geod` on the
  Moon sphere) equal to A, worst error **0.0038°**. So the terrain profile's
  azimuth index is true compass bearing, clockwise from north.
- **Horizons fixture agrees.** `server/test/fixtures/horizons_sun_im2_…` states
  in its header: *"Azimuth is measured clockwise from north: North(0) → East(90)
  → South(180) → West(270) → North(360)."* Same convention.
- **Independent pole check.** At a point 40 km from the north map edge, the only
  rays that run off the map early are those near azimuth 0 (min reach 39.5 km due
  north) — azimuth 0 points at the +y (top) map edge at longitude 0, as it must.
- **F-6 pairing.** At 2025-03-06 08:00 UTC the fixture Sun is az 70.544°,
  elev 2.069°. The terrain horizon in that direction is 1.228°, so the Sun is
  **lit** (2.069° > 1.228°). Plot: `out/direction_check.png` (regenerated by
  `direction_check.py`).

**F-6 result: PASS** — NASA azimuth and terrain azimuth are the same convention.

## Single point and grid (4-1)

- **One point** (IM-2 target), 360 directions to 150 km: **0.078 s**. All 360
  rays stay on the map (the point is ~165 km from the nearest edge). Horizon
  range −1.465°…4.009°, mean 1.00°.
- **Grid**, −400 m…+400 m east and north in 40 m steps (21 × 21 = 441 points):
  **2.1 s** (0.005 s/point). Covers ±400 m in every direction, so **4-1 is
  satisfied** (it asks for ≥ 320 m). Horizon range across the grid
  −1.497°…4.774°. No point had a ray leave the map before 150 km.
  Saved to `out/im2_grid.npz` (not committed).

Per point: 0.078 s is well under the 20 s gate, so the grid was run.

## The Miss profile file

`build_profile.py` writes `tools/terrain/im2_terrain.json` (≈1.16 MB, 441
points), the one file the Miss flow reads. It maps 1:1 onto the server's
`horizon_profiles` table — `site_id` (`im2`), `offset_east`, `offset_north`
(integer metres from the target) and `heights_deg` (360 values, index =
degrees clockwise from north) — and names the model (`terrain`) per the
contract that every reply and file names its model. The `.npz` and `.png`
outputs under `out/` are working artifacts and are not committed.

## Reporting (per AGENTS)

**Verified by automated test**

- lon/lat → pixel → lon/lat round-trip: worst drift 1.7e-11° (≈1 µm). (`roundtrip.py`)
- Direction convention = true geodesic bearing, worst error 0.0038° over the
  circle. (`direction_check.py`, part B)
- North/East map vectors, by the sign of the latitude/longitude response to a
  1 km step. (`direction_check.py`, part A)

**Verified by hand**

- Projection, size and pixel scale read from the file match the product name
  (80 MPP, 80°S). (`inspect_dem.py`)
- Elevation at the IM-2 target (5312.7 m) is plausible for Mons Mouton.
- Curvature formula reproduces the briefed 1.8° for a 6 km massif at 100 km.
- F-6 pairing: fixture Sun (az 70.544°, el 2.069°) is lit over the terrain
  horizon (1.228°); plot inspected.
- "Ray leaves the map" recording exercised at a near-edge point (149/360 rays
  off-map, min reach 39.5 km due north).

**Not verified (with reason)**

- Absolute vertical datum of the DEM vs other LOLA products — only the file's own
  values are used; no second source was consulted this block.
- The IM-2 target coordinates themselves — the PRD notes the LROC page now
  redirects to a viewer with no static coordinates; the owner-specified
  84.78 S, 29.13 E are used as given.
- Downstream use of these profiles by the window calculator and the Miss view —
  belongs to later blocks, not this terrain-prep step.
